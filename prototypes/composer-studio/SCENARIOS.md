# 输入区场景审查与扩展方案 · V9

## V9 当前状态与动态配置

展开态移除“写消息”、联系人和“收起”可见文字，仅保留收起图标与读屏标签。必要的状态提示、功能名称和无障碍标签仍需国际化，图标不能替代所有语言信息。

新增个人禁言、全员禁言、只读、已离开会话、发言间隔限制。禁言/只读不可编辑或发送；离线/重连/间隔限制可编辑但不可发送；麦克风权限问题不影响文字发送。所有受限状态显示原因、保留草稿；工具点击与失败重试也受同一策略约束。演示状态由选择器切换，不代表服务端权限鉴权或真实解除时间。

更多功能支持运行时传入 `actions` 数组，顺序即显示顺序。每项包含唯一 `id`、`label`、`icon`，及 `accept`（本地文件类型）、`panel`（voice/mention）、`onAction`（回调）、`reason`（不可用说明）之一。动态更新时修正页码；单页隐藏分页；空列表显示解释。页面“更多功能组合”可比较完整、媒体、自定义与空列表。

```js
window.flareComposerDemo.configure({
  actions: [
    {id:'file', label:'文件', icon:'file', accept:''},
    {id:'workflow', label:'审批', icon:'task', reason:'当前会话尚未开通审批'}
  ],
  state: 'allMuted',
  showSearch: false,
  showClose: false
});
```

合法状态：online、failed、disabled（个人禁言）、allMuted、readOnly、removed、offline、reconnecting、slowMode、permission、unavailable。未知状态或无效功能项抛出错误；发送中暂不接受状态切换，避免演示的延迟发送与状态修改冲突。正式实现必须基于真实服务器权限和异步发送结果处理竞争条件。

浏览器验证：展开顶部无可见文字，全员禁言时编辑和发送禁用且提示可见；切回正常后草稿保留，自定义三个功能按指定顺序显示。此接口仅为原型接口，尚未发布到四端组件。

## V8 当前富文本交互

取消段落下拉和“更多格式”入口，13 个格式操作全部平铺于横向工具栏。保留 28px 桌面行高及 44px 触屏热区；无滚动轨道，边缘淡出提示尚有内容。支持触摸横滑、触控板/滚轮、键盘左右与 Home/End 导航。链接仍按需打开地址输入框，非额外格式菜单。浏览器验证工具栏宽 352、内容宽 416，End 将滚动位置移动至 64，末尾“清除格式”可达，且不存在更多按钮。

## V7 当前规则与配置

富文本工具栏在精确指针环境从 32px 收至 28px；段落样式面板改为三列“图标 + 标签”短行，实测总高 137px。触屏仍采用 44px 命中高度，不以压缩热区换取视觉密度。

更多面板三个属性独立控制，默认均为 false：`showSearch`、`showTitle`、`showClose`。默认不显示顶部标题行，分页移至底部；搜索或关闭等任一项开启时恢复紧凑顶部行。隐藏关闭按钮不会隐藏工具栏 ×，避免没有退出入口。运行时关闭搜索属性会退出当前搜索并恢复分页。

原型可通过页面的“面板显示选项”实时比较，也可调用：

```js
window.flareComposerDemo.configure({showSearch: true, showTitle: false, showClose: false});
window.flareComposerDemo.getOptions();
```

配置仅影响更多面板的外观，不影响功能注册、发送、草稿和其他面板的关闭行为。参数仅接受布尔值，未知属性忽略。正式四端组件应映射为同名类型化 props/options；这不是已发布 SDK API。配置不持久化，刷新恢复默认。

已验证：默认极简、搜索/标题/关闭分别开启、搜索进行中关闭搜索入口、全部关闭后仍可通过工具栏退出，以及 28px 富文本栏与紧凑样式面板。

## V6 当前呈现规则

根据实际评审，撤掉常驻分类标签与搜索框。默认两行八项，新增能力进入下一页；分页与放大镜合并到轻量标题行。点放大镜时在同一行展开搜索，返回恢复分页。分组字段继续用于后台组织，不要求用户先选分类再找功能。不可用原因在点击后显示，避免每个按钮重复堆叠说明。已验证分页、搜索“文件”和退出搜索。

## 设计判断

当前视觉方向保留：白灰书写底座、20px 等距线性图标、小飞机发送、无方块选中背景、紧凑富文本。继续缩小图形的收益已经有限，下一步质量主要来自一致的状态转换和空间分配。

此前风险：更多功能不断堆叠、短屏叠加长文与附件、不同工具切换时暂存内容丢失、Escape 同时关闭面板与展开区、阅读位置在面板伸缩时跳动。V5 针对这些问题增加分组搜索、高度预算、录音预览暂存、图片选择保留、分层返回和阅读锚点处理。

## 空间与层级

聊天记录优先，正文其次，功能面板最后。扩展功能不应通过增大常驻底座来获得空间。常用操作保持固定顺序；低频操作放入“更多”的常用、协作、应用分组，可跨分组搜索。不可用的入口有明确说明，不静默失效。

高度预算按容器减去顶部导航、底部安全区和键盘占位计算。工具面板上限约为剩余高度的 42%，并限制在 100–236px；内容超出时内部滚动。标准/矮屏预览只是浏览器模型，不能替代 iOS keyboardLayoutGuide、Android IME insets、Flutter viewInsets、H5 visualViewport 的适配。

触屏格式热区 44，图标仍是 14，视觉紧凑与触控大小分开处理。字体用逻辑单位，正式产品应支持字号放大。颜色之外保留格式短标记、展开语义与未发送录音提示。

## 扩展契约

V5 的 `composerActions5` 用稳定 id、label、icon、group、panel/accept、reason 描述功能。新功能不需要改布局模板：注册后自动参与分组与搜索。此注册表仅验证产品结构，尚未成为四端共享代码。

正式实现建议统一 CapabilityDescriptor：

- `id`、`labelKey`、`iconKey`：跨端稳定身份、国际化、统一图标资源。
- `group`、`priority`、`supportedContexts`：分组、顺序、单聊/群聊/频道适用范围。
- `availability`：available / loading / unavailable / permissionRequired；附 `reasonKey` 和恢复操作。
- `draftPolicy`：none / preserve / confirmDiscard，明确离开面板时保留还是询问。
- `presentation`：inline / picker / external，统一宿主打开方式。
- `execute`：类型化命令，不让插件直接改编辑器或发送按钮状态。

状态拆为 Draft（RichDoc、选区、回复、附件）、Presentation（展开、格式栏、当前面板）、Connection、Permissions、PendingMedia；禁止用一个布尔 rich/expanded 决定所有行为。发送事件携带 conversationId 和 clientMsgId，失败恢复同一消息。附件需上传、取消、重试、过期资源状态；插件卸载要留下可解释的降级入口。

## 落地顺序

1. 先确认视觉和状态规则，再统一 token、图标与能力词条。
2. 四端实现统一 Draft/Presentation 契约，替换原型的 execCommand 与层叠事件覆盖。
3. 接入 SDK 的草稿、提及、上传和发送；用真实安全区与键盘验证。
4. 按上述矩阵验收手机、平板、桌面、大字号、读屏、长会话和权限变更。

本次产物仍是设计交互模型；`scenarios.js` 用于评审分组、转换和空间规则，不能直接当作生产级跨端状态管理实现。

## 本轮验证记录

- 搜索“任务”跨分组找到入口，点击显示不可用原因。
- 模拟录音中切到图片，再返回语音，恢复为 1 秒未发送预览。
- 620px 矮屏外壳实测：内容高 606px，更多面板 144px，聊天记录仍有 236px 可视高度。
- 展开态打开更多后按 Escape，关闭面板但保留展开态及正文。
- JavaScript 语法检查通过。以上为 Web 场景样本，不代表矩阵内所有条件已通过验收。
