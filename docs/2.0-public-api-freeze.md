# 2.0 Public API Freeze Review

> **Superseded — historical record.** This pre-closure review lists symbols that
> were later merged, internalized or removed (for example `FlareAppShell`,
> `FlarePrimaryButton`, `FlareTimeStamp`, `FlareChatHeader`, the `*Workspace`
> aliases). The current public surface is `docs/release/public-api-2.0.md`; the
> symbol-by-symbol changes are in `docs/release/migration/2.0-rc-to-2.0.md`. Do not
> use this page to decide what to import.

Candidate: **2.0.0-rc.1**. Status: **REVIEW_REQUIRED**, not a Stable freeze certificate.

## Authority

`spec/components.json` defines semantic roles; `spec/public-export-map.json` and platform package entries define imports. Generated signature checks detect missing props/events, not runtime equivalence. Do not import implementation paths from a consumer.

## Proposed Freeze Rules

- One body owns content; MessageBubble owns surface and MessageMeta owns time/status.
- Composer emits intents; host adapters own sends, uploads, recording permissions and capability decisions.
- ConversationHeader consumes identity, capabilities and resolved action configuration.
- Navigation accepts stable IDs, visibility, disabled states, badge and intents. No app-local rail renderer.
- AppKit remains optional and SDK-agnostic; no Core/Social client dependency in the package.
- Theme changes use semantic colors from the provider; no app-local light-only aliases.
- Only narrowly scoped slots/builders extend content. They must not replace built-in semantics silently.

## Native Message Content Additions

The current candidate adds `FlarePollContent`, `FlareTaskContent`, `FlareCalendarContent`, `FlareMiniAppContent`, `FlareAnnouncementContent`, `FlareRichTextContent` (Round 9, `richText`) and `FlareImageGroupContent` (Round 9, `imageGroup`) on Flutter, Compose and SwiftUI. `FlareLinkCardContent` is now represented on all three. They retain host data without converting everything to placeholder text. Since Round 9 a timeline reports poll and task intents (`vote`, `taskToggle`) on all four kits when the host takes them, and draws them read-only otherwise; no SDK op acts on either yet (S26), so the reference apps keep them read-only. Since Round 10 a timeline also offers the host's download on all four kits (`onMediaDownload`, the picture on screen with the message it belongs to), and `AdaptiveWorkbench` is no longer part of the surface (D18).

`FlareVoteOption.pct` is optional. Missing result data must not display 0%. Native LinkCardMessage accepts `icon` and `descriptionMaxLines`; null in Flutter/Swift or Int.MAX_VALUE in Compose preserves complete announcement text. Swift FileMessageView's optional `downloadLabel` supplies the download accessibility label.

## Naming And Internal Surface Review

- Vue exports `FlareComposer`; `EnhancedComposer.vue` is an implementation filename, not an additional public Composer API.
- `FlareChatHeader` and `FlareConversationHeader` still need semantic/export consolidation before Stable. Do not remove one without checking actual consumers.
- Native standalone bodies and runtime dispatchers now share the body implementations; Vue text and poll are consolidated in this closure pass. Other Vue standalone/business renderers still require review.
- Local consumer aliases/modifiers remain prohibited and are reported by the ownership gate, not added to an allowlist.

## Freeze Acceptance

Freeze remains blocked by complete renderer coverage, remaining duplicate presentation, native runtime actions, and executable cross-platform evidence. Re-run `npm run release:check` after these issues are resolved. A zero signature drift result alone cannot authorize 2.0.0.
