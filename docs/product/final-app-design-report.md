## 1. What Round 5 did differently

The four earlier rounds read screens. Round 5 re-graded the feature matrix from source — five read-only passes, one per app, each tracing a feature to the core op it calls and the failure it shows — and then fixed what that found. The difference is measurable: the re-grade moved 158 cells, and three of the changes were P0 defects that four audit passes had graded as working.

- **Tauri media never opened.** The app treated `media.resolve_access`'s *source kind* as a URL, so every received image, video, voice note and file resolved to a string like `remote`.
- **The SwiftUI and Compose timelines opened at the oldest loaded message** and did not follow the tail. Both kits had passing tests — they asserted widget order, not what a reader sees.
- **Flutter group mute wrote `muted`,** a field `social.group.update_my_group_settings` has ignored since it started taking `notifyMode`. The sheet and the group detail both looked like they worked.

The lesson is recorded for the next round: an audit that reads a screen tells you what it draws, not what it does.

## 2. What changed in the kit

- **A semantic icon system on four platforms.** Every public icon field takes one of 105 registry names (99 until Round 9); no public API takes an `ImageVector`, an SF Symbol name or an `IconData` any more. An unknown name draws the fallback glyph and warns once per name in a debug build, because a glyph written into a name parameter compiles fine and would otherwise be a silent question mark in production. Two ratchets keep it: kit-internal glyph references (vue 149, flutter 176, ios 76, compose 170) and app-side platform glyphs, now **0 in all five apps** (from 60 Flutter, 48 iOS, 32 Android). Fifteen names were nominated by the migrations and none was added in Round 5 — a name enters on four kits at once, with a real consumer on each. Round 9 decided the set by one rule and accepted six (`pin-self`, `diagnostics`, `card`, `id`, `join-request`, `storage`).
- **One pane below a usable chat width.** `workspaceDualPaneMinWidth` (navigation + list + a 360 px chat = 752 with the tablet rail) on all four kits, each measuring its own box rather than the window, dividing by the text scale, keeping the rail and turning a detail into a route. The shells report the presentation they settled on (`layoutChange` / `onLayoutChange`) so no host derives it from a width again. Nine new cases in `spec/application-layout-vectors.json`, passing unchanged on four kits. Round 9 then replaced this threshold and the layout policy's 720 with one rule for both component families (FR-110).
- **Settings rows tell information from actions.** `FlareSettingKind` gained `action`, and a `value` row stopped being a button on every platform: no control, no focus stop, no callback, read as one "label, value" element. A group setting that could not be read renders as 暂时无法读取 instead of a switch claiming "off" (`myMuted` / `myPinned` are nullable).
- **Timelines behave like chat timelines.** They open at the newest message, follow the tail while the reader is at the bottom, keep position after scrolling up and offer jump-to-latest with a count — on all four kits, asserted by what is on screen.
- **Copy, links and language.** Copy is offered only where there is text to copy (the core still says `canCopy` for media — SDK gap S22). Text links reach the host through `onOpenLink`, and where a host handles nothing, SwiftUI and Compose open http/https through the same `safeExternalUrl` gate the Vue kit uses; Flutter cannot (no URL launcher, lock files frozen) and that is a registered platform gap. The last English defaults went through the strings tables, Vue's default navigation included.

## 3. What changed in the apps

- **Web (golden):** older history pages past the local store through `sync.conversation_history_backfill` with a failure that keeps the history open and retries; forward, multi-select, pin, downloads, typing, presence, drafts and a normalised rich-text send; desktop search became a centred palette; full pages use a reading column; the chat's back control comes from the shell's report.
- **Tauri:** received media resolves through the app's own access-url reader; pins send `scope: 0`; the send ack's `serverId` reaches the row; the composer asks for its expanded toolbar on desktop windows.
- **iOS:** forward, reaction and image failures are visible; global search parses array replies; 重新连接 through `connection.notify_network_change`; the announcement read link works; the stranger-message switch shows nothing until it is known; a two-pane chat can push group and contact details. The iPad Split View bug is fixed at its root — `horizontalSizeClass` is `.regular` in a 700 pt window, so the app was squeezing the chat to ~380 pt.
- **Android:** account-scoped view models are re-keyed on sign-out (the moments feed leaked between accounts), failed uploads and failed reads are reported, the keyboard no longer covers the composer.
- **Flutter:** the group notification mode is written the way the op takes it, the connection notice reaches a pushed chat and the moments tab, and a denied gallery permission says so.

## 9. Round 12

Round 12 took what Round 11 had left that needed no account, no device, no CI hardware and no SDK owner. It closed three PARTIAL entries, opened four of its own and left the friction register with **one** PARTIAL (FR-095's remaining shell items) out of 155 entries.

**The layout asked the wrong question.** Every width rule in the Vue kit asked `@media`, so a chat in a 380px column of a 1600px desktop got the desktop avatar gutter, the desktop bubble widths (`34vw` of the *window*) and the desktop composer. Round 10 had fixed the components — they read the shell's mode — and left the stylesheets, which is exactly the kind of half that survives a round because nothing can see it: the visual baselines render each fixture at a width where the pane and the window are the same number, so they agree with both answers. The fix names the three boxes that decide a chat's layout (`flare-timeline`, `flare-chat`, `flare-composer`) and lets the rules ask those, with `cqw` where they used `vw`. A container query cannot style its own container, so the composer's own bar reads a `composer--wide` class the composer sets from a ResizeObserver on its own box — and the two measure different boxes, which is worth knowing: a container query reads the content box, so a 909px composer with 6px of padding answers 897 and would drop to the phone layout three pixels early.

**A promise nobody had run.** Holding the CSS up to the package's own browserslist found it promised Chrome 87 while the styles used `color-mix()` 213 times, with no `@supports` and no fallback anywhere — on a promised browser those declarations are dropped silently and borders and backgrounds disappear. The floor is now Chrome 111 / Edge 111 / Firefox 113 / Safari 16.2 and a gate reads the features the CSS actually uses (FR-152).

**Two of the 38 "missing" slots were never missing.** The slot gate read idiomatic names from `platformAliases.<platform>.slots` only, so `ContactList.trailing` (Flutter's `trailingBuilder`) and `ChatWorkspace.context` (Flutter and Compose's `contextBanner`) sat in the constructors for three rounds while the contract said they did not exist. Fifteen more pairs were built on all four kits — a list that is empty can now say what to do about it, and a screen header can say what the screen is reached through — and the remaining 21 stay narrowed **with a written reason each**, which the gate now requires. A narrowing that says nothing is how the two bookkeeping errors hid.

**One contact index, four kits.** FR-044's three remainders (Flutter's level-2 hanzi, every Chinese name on Android 8 and 9, a polyphonic character read differently per kit) had one cause: two kits carried their own table while two asked the platform. They now share a generated table of every character in CJK Unified Ideographs, produced from the same collation the other two read, with a 55-character vector table all four check against. Compose dropped the ICU transliterator with it, which also removed an ordering only Compose had: it read 安娜 as "an na" and sorted it after "alice", where the other three put Chinese names first.

**The docs were lying quietly.** Nine website demos passed props and listeners that had been renamed or had never existed — `conversation-type`, `group-start`, `count`, `connection-tone`, `status`, `@close` — and Vue forwards what it does not recognise, so every page rendered a component nobody had configured. A gate now reads each component's own `defineProps` / `defineEmits` (FR-155). Two of those were Round 11's own leftovers, which is the honest reason to run the website suite in a round that did not touch the website.

**A received file can be kept.** The three native apps save one now, with no new dependency, in the shape each platform asks for: Android writes `Download/Flare` through MediaStore behind a sheet, iOS hands the downloaded file to the system panel where Save to Files already lives, and Flutter reaches both through the channel it had. A sender's file name is a string, not a path, so each host keeps only its last segment.

**A host nobody had built.** Building the Flutter app for iOS to check the new file path found that its iOS host had not compiled since Round 11 wrote it: the avatar picker used `PHPickerViewController` against a project targeting iOS 13, and the engine callback read a member the installed Flutter's bridge does not have. Two hard Swift errors — so the picture-saving and avatar-picking Round 11 reported for the Flutter app on iOS had never run. `flutter analyze` does not read Swift, and the round had verified the Dart side and the Android host (FR-156). The lesson is narrow and repeatable: a round that writes platform host code builds that platform in that round.

## 10. Round 13

Round 12's own list of leftovers was, by construction, all things this program cannot do: an account, a device, CI hardware, another team's SDK. So Round 13 did not work from that list. It looked at the code again and asked what is wrong today — and the first thing it found was Round 12's own work.

**The conversion had moved the rules and left the numbers.** Round 12 put the timeline's rules behind `@container flare-timeline` and reported that a chat is laid out for its own box. But the two numbers those rules read — how wide a bubble may be, how much room the timeline keeps at its edges — were still set on `:root` behind `@media`. Measured on the fixture: a 380px pane of a 1600px window was still getting `min(62%, 640px)` and a 16px gutter, which is the desktop answer. The round's own test could not see it, because all it asserted about a bubble was that it fits inside the pane, and a desktop-capped bubble does. The numbers now sit on the boxes that own them and the test asserts the numbers; undo the conversion and it is the only one of the three container tests that goes red (FR-157).

Two more defects fell out of that pass, both older than Round 12: a media body capped itself at `72vw` and nothing else, so a picture inside a bubble narrower than that hung over the edge of the page; and the bubble's `max-width: 100%` guards had been grouped with the phone rules, inheriting a width condition they never needed, so a bubble used outside a timeline had no guard at all. And one defect in a test: the visual-regression loop that asserts the gutter per viewport was reading one iteration behind, because a container query re-evaluates after layout and the loop only waited for the window.

**Two documents were counting themselves wrong.** The friction register's opening sentence — the line a reader trusts for where the work stands — said 148 FIXED and 1 PARTIAL while its own rows said 151 and none; the last partial had been finished two rounds earlier. The feature matrix got a recount gate in Round 10 for exactly this; the register, which is read more often, had none. It has one now, and it found five drifted figures on its first run (FR-159).

**Eight selectors styled nothing.** `chat-composer-stack`, `workbench-details`, `workbench-sheet--side`, `preview-card`, `start-dialog-card`, `web-shell`, `chat-route` and `flutter-list-header` are named by the kit's stylesheets and produced by nothing — not the kit, not the demos, not any of the five apps. A general gate for this is deliberately not shipped, for the reason FR-102's behaviour counters were deferred: a class name can be built at runtime, come from naive-ui, or be generated by a Vue transition, so a grep-based check reports about a hundred names of which most are alive. What would work is scanning the rendered previews rather than the sources, which belongs with the visual pass (FR-158).
