# App component consumption

Goal: most generic IM UI comes from `flare-im-design`. An example app keeps only app business (product flows, information architecture, moderation taxonomy) and host adapters (SDK mapping, platform glue); anything another IM app would reuse belongs in the kit.

This document maps, per app and per feature, what the apps need, what they take from the kit, what they still build themselves, and what the kit lacks. Date: 2026-09-14; the evidence is a snapshot taken before the compile-blocked files were edited later that day, and file:line references follow that snapshot. Rounds 1 to 3 moved many of the app-local rows below into the kit; they are not re-graded here (current state: `design-system-escape-hatches.md` and `docs/components/component-catalog.md`). Evidence: per-app code audits, the Vue kit API audit, compile runs against the kit working tree, and the catalog usage census. Reference roles: web is the golden app, iOS the second reference app, Tauri, Flutter and Android are parity apps.


> **Round 5 update (2026-09-16).** The census below is the audit snapshot. After the Round 5 implementation, the catalog components each app references are: web 50, Tauri 65, Flutter 50, iOS 47, Android 45, and 78 of the 150 catalog components are referenced by at least one app. Method: every `Flare*` tag or identifier (Vue templates, Dart and Swift sources) and every `com.flare.im.ui` import in the app sources, mapped to catalog components through each platform's symbol in `spec/components.json`; types, models and string tables are therefore not counted, and a component used only inside another kit component does not appear. The kit-reference gate reads 0 on every count for all five apps (naive-ui, deep kit imports, vendor glyph imports, visual literals, Material and bespoke primitives), and the style hatches are web `:deep` 0 / `!important` 2 and Tauri `:deep` 4 / `!important` 0, with no selector reaching into kit internals. Behaviour the apps still rebuild from kit parts is measured in `design-system-escape-hatches.md` sections 3b and 3c; per-screen composition is in `screen-inventory.md`.
