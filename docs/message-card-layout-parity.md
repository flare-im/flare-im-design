# 消息卡片跨端尺寸与交互

共享设计库统一 Vue（Web/Tauri）、Flutter（移动/桌面）、SwiftUI、Compose 的消息卡片视觉尺寸。使用逻辑像素；系统字体栅格化允许细微差异，不使用桌面专属倍宽。

| 内容 | 统一宽度 | 窄屏行为 |
| --- | --- | --- |
| 红包（普通、拼手气、专属、所有状态） | `componentRedPacketCardWidth` = 248 | 不超过父级可用空间 |
| 普通富卡片、插件卡片、业务卡片 | `componentRichCardWidth` = 320 上限 | 不超过消息行可用空间 |
| 语音/视频通话记录 | 随内容收缩，最多 320 | 状态换行，媒体名称可省略溢出 |
| 文字/文件/音频与媒体消息 | 保留既有内容布局与共享气泡比例/媒体约束 | 头像、工具栏和元数据占用可用空间，不扩大卡片表面 |

消息行、声明式插件渲染器和回复引用容器不能把卡片的宽度上限变成填充宽度。收发两侧共享同一表面，时间与回执在卡片下方靠尾侧对齐。应用只负责数据映射和交互回调，不覆盖共享组件内部样式。

红包统一使用 14 的四边内边距、30×39 图标、12 的图文间距、14 号半粗祝福语、12 号状态和 10 号中粗页脚；文本行高为 `lineHeightSnug`（1.4）。状态可换行；分隔线上方间距 12、下方间距 8。页脚类型与收件人相隔 8，品牌靠尾侧，中英文名称与原生共享文案一致。未领取状态的次要文字透明度 0.85，已领取/领完/过期/退回使用已有淡化语义色；不改变金额和状态规则。默认红包高度约 102.4，Flutter 字体行盒取整为 103。

已结束单聊满足 `canCallBack` 时，点击整张通话记录打开共享回拨确认弹窗，取消不发起通话，确认后才通知宿主；不显示独立回拨按钮。群通话保留「加入」。忙碌、不可用或缺少回调时不接受操作，确认前重查当前能力，重复点击不能重复通知宿主。可操作通话卡片至少 48 高，保留媒体、状态和本地化回拨提示。

引用区域独立于通话回拨和红包打开区域，保持定位原消息的点击与无障碍语义。插件不可用仍显示记录；卡片的忙碌、不可用、只读和已结束状态延续现有契约。

本次修复的差异：

- SwiftUI 通话外壳的最大宽度 frame 拉伸了背景，替换为在父级范围内测量自然宽度。
- 原生通话记录仍有独立回拨按钮，现与 Flutter/Vue 的确认流程一致。
- Flutter 声明式红包分支的横向拉伸覆盖了红包宽度，手机测得约 322、桌面测得 640；现在绘制与交互区域均不超过 248。共享外壳也能抵抗紧约束。
- Web/Tauri CSS 曾将普通富卡片改为 332/348、紧凑卡片改为 292/304，现统一回到共享 320 上限。声明式插件的隐式 grid 列在 180 宽容器中仍占 248，现明确允许该列收缩。
- 原生红包的字号、内边距、状态截断和页脚间距与 Flutter/Vue 不同，已按上述规则统一。

验证范围包括红包、声明式红包、普通插件卡片、通话、引用区域、消息行元数据；同时检查 180 窄容器、常见手机和桌面宽度、明暗主题、大字体、收发两侧、长状态和不可用/忙碌状态。没有重做 RTC 通话页、媒体裁剪策略或其他业务页面；真机 RTC、所有系统字体及所有品牌的逐像素比对不在本次验收范围内。
