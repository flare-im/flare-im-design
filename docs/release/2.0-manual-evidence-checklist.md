# 2.0 Manual Evidence Checklist

候选身份见 `artifacts/release-2.0/candidate.json`；机器可读的需求图是 `spec/release-requirements.json`，逐条判定结果是 `artifacts/release-2.0/evidence-manifest.json`（`node tooling/check-release-evidence.mjs` 生成）。台账本身仍是 `spec/manual-evidence.json`：`tooling/release-policy.mjs` 只认 `status: PASS` 且 `evidence` 非空的条目。

本文件做三件事：给证据分级；把 13 条 manual evidence 逐条定性（其中 6 条此前**全仓没有定义**，本文件第一次给出判据，判据全部取自仓库里已有的预算与手工用例，没有新造数字）；规定证据文件格式，让一条设备结果能绑定到候选 id、能被过期检测。

## 1. 证据等级

| 等级 | 名称 | 含义 | 例子 |
|---|---|---|---|
| L1 | STATIC | 代码 / 配置审计 | `check-security-boundary`、`release-security-audit` |
| L2 | BUILD | 能编译、能打包 | `vue-build`、`ios-app-build` |
| L3 | SIMULATED | 模拟环境：单元 / 契约测试、浏览器媒体仿真、模拟器 | `accessibility-hardening.spec.ts` 的 `forcedColors: "active"`、Flutter widget Semantics 测试 |
| L4 | RUNTIME | 真实运行的产物，非设备 | clean consumer 在 Chromium 里挂载、`performance-budget` 真挂 1000 会话 |
| L5 | PHYSICAL_DEVICE | 真实设备 + 真实系统能力 | VoiceOver、TalkBack、真机帧率 |
| L6 | PRODUCTION_LIKE | 真实后端 + 真实运行环境 | `web-live-sdk`：真 Chromium、真 web app、真 SDK、真服务端 |

需求要求的等级是下限，不能用低等级冒充：VoiceOver 不能用 L3 的 axe 结果；设备矩阵（`docs/device-accessibility-test-matrix.md`）原文规定"A simulator result may support debugging but cannot change a physical-device row to PASS"；手势用例（`docs/gesture-contract.md`）规定"Simulator execution is diagnostic evidence only"。

## 3. 定义

### 3.1 A11Y-IOS-VOICEOVER（在设备矩阵之上补充的任务）

设备矩阵的步骤不变。认证简报要求的五个核心任务逐条记录：

1. 会话列表：找到未读会话，读出标题、未读状态 / 数量、最后一条消息、时间。
2. 聊天：逐条读消息，至少能区分发送者、内容、状态。
3. Composer：聚焦、输入、发送。
4. 消息菜单：打开、在动作间移动、执行一个动作、关闭，焦点回到消息。
5. Dialog / Sheet：焦点不逃出模态。

额外检查（出现即记 FAIL 并写明组件）：重复朗读；无意义图标被朗读；"button button"；时间戳过度朗读；一条消息的全部元数据被拼成一个巨大字符串；空按钮；未标记的可选控件。

### 3.2 A11Y-ANDROID-TALKBACK

与 3.1 同级，另加：系统返回、手势导航、TalkBack 焦点、Bottom Sheet 可达性、从权限对话框返回后的焦点恢复。

### 3.3 PERF-IOS

- 环境：物理 iPhone，60 Hz 与 ProMotion（120 Hz）各一台；release 构建；Instruments（Animation Hitches + Time Profiler + Allocations）。
- 数据集（认证简报场景）：1000 会话；5000 消息；大量图片消息；长文本；大量 reactions；快速连续入站消息；Composer 连续输入；动作菜单打开。
- 预算（全部取自 `docs/performance-baseline.md`，不新造）：稳定滚动 p95 帧 < 16.7 ms；无单帧 > 100 ms；120 Hz 设备同时报告 8.3 ms 与 16.7 ms 两个阈值，不得隐藏高刷丢帧。
- 同时记录基线（没有预算的项只记录、不判 P0）：冷启动时长、打开会话延迟、消息渲染延迟、CPU、峰值 / 稳定内存。
- 采集规程：三次冷启动、五次热启动；p50 / p95 / p99 帧；设备型号、OS、刷新率、构建模式、数据集种子。
- PASS：预算项全部满足；基线项齐全；无灾难性问题（卡死、> 1 s 冻结、OOM）。

### 3.4 PERF-ANDROID

同 3.3；工具为 Macrobenchmark（`FrameTimingMetric`）或 Android Studio Profiler；设备为 60 Hz 与 120 Hz 各一台，API 26+。

### 3.5 GESTURE-IOS / GESTURE-ANDROID

五条用例来自 `docs/gesture-contract.md`：`GEST-MESSAGE-REPLY`、`GEST-CONVERSATION-ACTIONS`、`GEST-VIEWER-ZOOM-BACK`、`GEST-COMPOSER-KEYBOARD`、`GEST-VOICE-CANCEL`。逐动作记录见 [native-gesture-matrix.md](native-gesture-matrix.md)。PASS：五条在该平台全部 PASS，每条附真机视频、输入方式、OS / 构建、期望 / 实际、测试人。

### 3.6 RESOURCE-IOS / RESOURCE-ANDROID

- 循环（认证简报）：进出会话 ×20；消息动作打开 / 关闭 ×50；Sheet 打开 / 关闭 ×50；图片预览打开 / 关闭 ×20；Composer 聚焦 / 失焦 ×30；原生选择器打开 / 取消 ×10。
- 观察：内存、监听器数、订阅、定时器、WebSocket / SDK handler、媒体流、相机、麦克风。
- 判定：**不要求**内存回到初始值。FAIL 条件是：持续单调增长；重复 listener / subscription / callback；重复网络请求；陈旧 DOM / 原生句柄；循环结束后相机或麦克风仍占用。已有预算：线程打开 / 关闭 20 次后回到稳定内存的 10% 以内（`docs/performance-baseline.md`）；只有当前媒体项在播放；录音中切到后台再回来不发送任何片段且资源已释放（`GEST-VOICE-CANCEL`）。
- Android 另加：录音中进程被杀后恢复，无卡死的录音器。

## 4. 证据文件格式

每条设备结果写成 `artifacts/release-2.0/{accessibility,performance,native}/<ID>.json`，并在 `spec/manual-evidence.json` 里把该条改为 `"status": "PASS", "evidence": "<该路径>"`。`tooling/check-release-evidence.mjs` 会核对文件里的 `candidateId` 与当前候选一致，否则判 STALE。

```json
{
  "requirementId": "A11Y-IOS-VOICEOVER",
  "candidateId": "flare-im-design@2.0.0-rc.1+<16 hex>",
  "level": "L5_PHYSICAL_DEVICE",
  "result": "PASS",
  "device": "iPhone 15, A3090",
  "os": "iOS 18.6",
  "build": "flare-core-ios-app Release, built from the candidate",
  "locale": "en-US",
  "settings": { "voiceOver": true, "textSize": "default", "theme": "light" },
  "steps": [{ "step": "Task 1", "expected": "...", "actual": "...", "result": "PASS" }],
  "evidenceUris": ["https://<recording store>/..."],
  "tester": "<name>",
  "date": "2026-09-14"
}
```

不写入任何账号密码、token 或个人数据；录屏里出现的测试账号只能是 `ui2-release-*`。
