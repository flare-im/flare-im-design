# Component Architecture Audit（2.0.0-rc.1）

范围：spec/component-catalog.json 全部 154 个 public component × 四端实现，外加 packages/vue-im-ui/src/components/index.ts 里 29 个未登记进 catalog 的公开导出。数据来源：plans/audit-2026-09-12/inventory.json（自动统计：四端 symbol、行数、props、测试/demo/visual 覆盖、kit 内部与五个 example 的真实引用）与同日 5 份设计审计 findings。所有 Status 只用 KEEP / REFACTOR / MERGE / SPLIT / INTERNALIZE / DEPRECATE / REMOVE。

分层映射（用户五层模型 ← catalog layer/category）：L1 = general-ui 的 General/Form；L2 = general-ui 的 Feedback/Navigation/Overlay + Layout 里的 ScreenHeader；L3 = im-ui 域组件；L4 = 组合/场景（*Workspace、*Panel、*Sheet、*Detail、Call*、Composer 等）与 workspaces/patterns/appkit；L5 = ConfigProvider（平台契约，当前只有 Vue）。用户简报里的理想名（ChatView/MessageItem/ChatComposer/MemberItem）对应 catalog 的 ChatWorkspace/MessageBubble/Composer/ContactItem。

Public 列 = 该 symbol 是否真的从各端公开面可达（vue components/index.ts；flutter facade export；Swift `public struct`；Kotlin 非 private @Composable），顺序 vue/flutter/ios/compose。

决策规则（按顺序，先命中先用；逐组件的例外见表中『原因』）：
1. 明确证据的覆盖决定（审计 findings + inventory）优先。
2. 同一职责存在两份实现（名字不同、平台不同或公开/未登记）→ MERGE 到语义正名的一份。
3. 在任何端都没有消费者、也不被 kit 内部使用、且只是另一组件的薄包装或别名 → INTERNALIZE / DEPRECATE / REMOVE（不确定外部消费者时选 DEPRECATE）。
4. Vue > 600 行或 boolean props ≥ 8 或 props > 20 且混杂多种职责 → SPLIT（按职责）或 REFACTOR（API/实现），不按行数机械拆。
5. 行数 < 70、无独立状态与 API、生命周期绑定父组件、example 零使用 → INTERNALIZE。
6. 其余 KEEP；example 零使用的 KEEP 组件成熟度标 BETA。
