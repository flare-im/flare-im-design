## 4e. 工作区状态（P0-8，2026-09-13）

- **`WorkspaceFrame` 四端现在真的渲染状态**。Compose 的 `WorkspaceFrame` 与 iOS 的 `WorkspaceFrameView` 之前是一行转发到 AppLayout，连 `state` 参数都没有；现在两端都接 `state` / `onRetry` / `onEmptyAction` / `onBannerAction`，和 Vue、Flutter 同一套。宿主什么都不传时行为不变（全部 ready）。
- **新事件 `emptyAction`**（四端）：空态在有标签且宿主绑了处理器时给出「下一步」。判定条件和重试一样是三件套——状态对、标签非空、宿主能接——一个点了没反应的按钮比没有按钮更糟。
- **`WorkspacePaneState` 增加 `description`**（四端）：空态标题下的第二行，说明用户能做什么。
- **Flutter `FlareWorkspaceState` 的窗格类型换成 `FlareWorkspacePaneState`**（原来是 `FlareViewState<Object?>`，和 `FlareConversationWorkspace` 各用各的）。`offline` 不再是窗格状态：连接状况属于横幅，挂在可能仍能读缓存的窗格之上，所以 `FlareWorkspaceState` 增加了 `banner`。kit 之外没有消费者。
- **frame 的兜底文案独立成 `workspaceFrame.*`**（`loading` / `empty` / `failure` / `retry`，四端 strings 各一份）。它同时承载通讯录、设置、搜索、媒体，不能沿用会话工作区的「暂无会话」。
- **两套断点合并成一处**：`shared/contracts/layout.ts` 现在导出 `FLARE_BREAKPOINT_TABLET_MIN`(600) 与 `FLARE_BREAKPOINT_DESKTOP_MIN`(900)，`useViewport` 从这里取值。`FLARE_BREAKPOINT_IPAD_MAX` 由 1023 变成 899：900–1023 这一段过去同时是「桌面 CSS」和「iPad 组件行为」，布局已经三栏了组件还在出底部弹层。依赖 `useFlareAdaptive` 在 900–1023 返回 `ipad` 的宿主会看到它变成 `pc`。
- **`SceneList` 改用 kit 部件**：动作是 `FlareButton size=sm`（destructive 走 danger），行是设置分组卡的解剖，loading / empty / failure 走 `WorkspacePane`。它自带的 `<progress>`、裸 `<p>` 空态和描边按钮删除；依赖 `.scene-list button` 选择器的宿主样式要改。

## 4f. 输入法与键盘（P0-9，2026-09-13）

- **组字中每个键都归输入法**（行为变更，四端）。`resolveFormKeyboardIntent` 的组字守卫从「Tab 之后」前移到第一句。此前组字中按 Tab 会返回 `tabForward` 把焦点挪走，而输入法本来要用 Tab 选候选词；Escape 和方向键同理。现在规则只有一句：组字中一律 `none`。依赖「组字时 Tab 仍然切换焦点」的宿主会看到变化。
- **composer 的发送判定改为问契约**（Vue / Flutter）。此前 Vue 读 `event.isComposing`、Flutter 读 `composing.isValid`，契约存在但发送路径不用它。Vue 另外补上 `keyCode === 229`——部分 Android / Windows 键盘只报这个旧信号，`isComposing` 是 false，此前这种键盘上组字按 Enter 会把半个词发出去。
- **Compose 超长时截断而不是丢弃**。`BasicTextField` 原来在 `it.length > maxLength` 时整条丢弃更新，state 不动、字段回滚，输入法继续对着一个已不存在的值组字，中日韩输入在边界上静默丢字。改为 `composerTextWithinLimit(next, maxLength)` 截断，`Composer` 与 `Input` 两处。宿主可见的变化：打满上限后继续打字，现在会保留前 N 个字符而不是整段不动。
- **新契约与门禁**：`spec/form-keyboard-contract.json`（18 条向量）+ `node tooling/check-form-keyboard.mjs`，已接进 `npm run check` 与 `release:check`。新增键盘行为要先进向量表，四端测试都补上才会绿。

## 4g. 列表性能（P0-10，2026-09-13）

- **`FlareConversationList` 现在自己兜底高度**（`height: 100%`）。此前它声明 `overflow-y: auto` 却不约束自身高度：宿主没给盒子时它长到内容全高，`clientHeight` 等于整份内容，虚拟窗口于是覆盖全部行——1000 条会话渲染 1000 行，没有任何报错。`100%` 在父高为 auto 时解析回 auto，所以只在宿主真给了盒子时生效；把列表放在 auto 高容器里的宿主行为不变（仍然渲染全部行，因为那本来就没有可滚动的盒子）。
- **`MessageList` 的性能承诺改写，实现不动**。`VIRTUALIZATION_THRESHOLD = 25_000` 意味着它对任何现实规模都不窗口；代码注释写明了原因（固定行高估算配不上高度可变的富文本行，翻页时滚动条会跳）。契约里「O(visible + overscan)」换成真实保证：**组件渲染宿主加载了多少就有多少**。宿主要自己守住已加载窗口，契约把它写成 `hostMaxLoadedMessages: 400`。无上限地累积已加载消息的宿主，DOM 也会无上限地涨。
- **新预算与关口**：`spec/performance-contract.json` 增加 `measuredBudgets`，`website/tests/performance-budget.spec.ts` 真挂 1000 会话 + 5000 消息来验；release-check 新增 `performance-budget` 关口。数字与未覆盖项写在 `docs/release/performance.md`。

## 4h. 安全边界（P0-11，2026-09-13）

- **新增 `safeExternalUrl` / `isSafeExternalUrl`（四端）**：Vue `@flare-im/vue-ui/contracts`、Flutter `flare_im_ui`、Compose `com.flare.im.ui`、SwiftUI `FlareIMUI`（iOS 拼写是 `safeExternalURL`）。宿主打开消息里的链接前应当用它判定——kit 把 URL 通过事件报上来、由宿主跳转，这条规则两边必须是同一条。只放行 http / https，规则与理由写在 `docs/release/security-boundary.md`。
- **`LinkCardView` 的 URL 判断换成共享闸**，行为不变（仍然只开 http / https），差别是宿主现在能拿到同一个函数。
- **新门禁 `check:security-boundary`**，已接进 `npm run check` 与 `release:check`。它会拦三件事：Vue 包里出现登记之外的 `v-html` / `innerHTML`；组件新绑 `:href` 却没在 `spec/security-boundary.json#anchors` 里说明怎么把关；markdown 渲染器的 `html: false` 被改掉。新增这类代码要先进契约。

## 4m. 认证阶段的两个修复（2026-09-14）

- `quotedTextPreview` 由**发送方**计算并随消息发出，用 kit 的摘要词条；接收端即使没有那条原消息，也能读到同一行字。
- 引用内容里只有 `quotedSenderId`，没有名字：宿主在映射消息时把自己知道的名字写成 `quotedSenderName`，否则气泡会把用户 id 直接显示出来。

**三个原生 kit（Round 6 · B1）**

- 新增一句话摘要：Flutter `flareMessagePreviewText(content, strings)` / `flareReplyTargetFor(message, strings)`（`lib/src/models/message_preview.dart`）；SwiftUI `flareMessagePreviewText(_:strings:)` 与 `FlareReplyTarget.init(replyingTo:strings:)`（`Models/MessagePreview.swift`）；Compose `flareMessagePreviewText` / `flareMessageReplySummary` / `flareReplyTarget`（`MessagePreview.kt`）。`strings` 是必填参数——给默认值会悄悄把中文发给英文宿主。
- `FlareStrings` 各加 29–31 个 `preview*` 词条，键名与 Vue 的 `preview.*` 一一对应，中文取 Vue 现有文案。**宿主不要再自己拼 `[消息]`**：空摘要的兜底是 `previewMessage`。

- 空相册的措辞四端统一为 `[多图]`（此前 Vue 与 Flutter 会说 `[多图] 0 张`），规则写进共享表。

**三个原生应用**

- 消息操作表里的 `reply` 不再隐藏；回复目标用 kit 的构造器生成，输入框接 `replyTo` / `onCancelReply`（取消、切会话、发送成功清空，发送失败连同文字一起还回来）。

**请列表显示某条消息（Round 6 · B2，四端）**

- 新增 `scrollToMessage(id)`：**Vue 不变**（组件实例上早就有这个方法）；Flutter 与 SwiftUI 新增 `FlareMessageListController`，Compose 新增 `FlareMessageListState` + `rememberFlareMessageListState()`，都通过列表的 `controller`（Compose 拼作 `state`）传入。返回「列表当时有没有这条」。
- **Flutter 破坏性**：`FlareMessageList.controller` 由 `ScrollController?` 改为 `FlareMessageListController?`，不留别名。控制器自己创建并释放那个 `ScrollController`，宿主要原始滚动能力就读 `controller.scroll`。
- **Compose 破坏性**：`MessageList` 的 `listState: LazyListState` 参数换成 `state: FlareMessageListState`（内部持有那个 `LazyListState`），同样不留别名。两个仓库里都没有人传过 `listState`。
- 句柄是各端**既有** locate 路径的入口，不是第二套滚动：锚点、Reduce Motion、停止跟随尾部都沿用原来的实现。
- 宿主要知道的两条规则：**（1）按行 id 问**——引用块携带的 `messageId` 在被引用消息未加载时是核心 id，而列表的行 id 对自己发的消息是 `clientMsgId`，不换算就会对着屏幕上的消息说「找不到」；**（2）先让自己的一次构建过去再问**——句柄按列表最近画的那一遍回答。
- 三个原生应用因此把「点引用跳原消息」做成一次点击：翻历史 → 问列表 → 真就结束、假才提示。

**一条引用只用一个 id（Round 6 · B3，四端）**

- **`FlareReplyTarget.messageId` 永远是被引用消息的核心 id**（此前「加载了就是行 id、没加载就是核心 id」的混合体）。kit 自带的回复目标构造器（Flutter `flareReplyTargetFor`、SwiftUI `FlareReplyTarget(replyingTo:strings:)`、Compose `flareReplyTarget`）也改成发核心 id。
- 三个原生 kit 的 `FlareMessageData` 新增 **`serverId`（可空、带默认值）**：这一行在核心里的 id（Vue 的 `MessageLike` 本来就有）。现有构造调用不受影响。
- **列表按两个 id 认行**：行 id 与核心 id 都算命中，用在两处——气泡判断「被引用消息在不在列表里」，以及 `scrollToMessage`。宿主因此**不再做任何换算**，把 `onLocateMessage` 给的 id 原样传回去即可；B2 里加的 `rowIdFor` / `TimelinePaging.rowId` / `loadedMessageRowId` 全部删除。
- **Vue 的两处对齐**：列表现在自己显示它正在画的那条被引用消息（此前永远抛给宿主），只有不在时才抛 `locate-message`；引用块只有在「点了会有反应」时才画成按钮。
- 宿主要做的只有一件事：映射消息行时填上 `serverId`。`tooling/check-ui-reuse.mjs` 现在要求三个原生应用的消息映射里出现它——删掉那一行会让门禁红，而不是让「点引用说消息不存在」悄悄回来。

**被定位的那条落在哪儿（Round 6 · B4，Compose）**

- 四端统一：被定位的行落在视口正中。Vue 的 `block: "center"`、Flutter 的 `alignment: 0.5`、SwiftUI 的 `anchor: .center` 本来就是这样；Compose 此前直接 `scrollToItem(index)`，行贴在视口顶边，上方给它上下文的那几条全在屏幕外——同一次点击在 Android 上读起来是另一回事。
- 宿主不用改代码：偏移在 kit 内部算，点引用与 `scrollToMessage` 共用同一条 locate 路径，所以两个入口落点一致。
- 做法：先用「已画出的行的平均高度」估一次偏移滚过去，该行布局完成、真实高度已知后再静默校正一次（`scrollToItem`，不是第二次动画），读者看到的是一次移动。行本身不低于视口高度时仍然贴顶——没有可居中的空间，往下推只会挡住开头。
- 纯函数 `centeredRowOffset` / `estimatedRowSize` 有 5 条 JVM 测试；位置本身没有在本机验证过（无模拟器），`androidTest` 里那条「行中心距视口中心 24 dp 以内」的断言只编译过，属于外部验证步骤 B4。

**侧滑回复（Round 6 · B5，三个原生 kit）**

- `onSwipeReply` 三端都早就有，但此前是**三套不同的手势**：Flutter 按行宽 20% 触发（手机 78 pt、平板 160 pt），iOS 与 Compose 各按 56 的固定值——而 Compose 那个 56 是**像素**，3x 屏上约 19 dp。现在三端同一条规则，共享表是 `spec/swipe-reply-vectors.json`：只认尾边方向（RTL 镜像）、横向位移不足竖向 1.25 倍时让位给列表滚动、跟手到 56 后按 0.35 阻尼最多 72、56 上膛。
- **宿主要做的**：接上 `onSwipeReply`，进你菜单「回复」那条路径（同一个引用构造器，不要另写一套用词）。三个示例应用各一行。
- **行为变化**：侧滑过程现在看得见——行跟手，注册表的 `reply` 图标在上膛点正好到达满强度。此前 iOS 与 Compose 全程没有任何反馈。
- **Flutter 破坏性（行为）**：消息行不再被 `Dismissible` 包着。如果你依赖过 `Dismissible` 的 key（`swipe-reply-<id>`）做测试，那个 key 还在，但组件类型变了。
- 系统提示行、已撤回消息、多选模式仍然没有侧滑；菜单里的「回复」仍在，侧滑永远不是唯一入口。

**跳过去之后「是这一条」（Round 6 · B6，四端）**

- 定位落点的那一行现在会被标记一个窗口:气泡后面一圈主色的光环,`spec/locate-highlight-vectors.json` 定死窗口(1600 ms)与三个停靠点(0 ms: alpha .36 / spread 0;700 ms: .18 / 10;1600 ms: 0 / 18),线性插值。三个原生 kit 此前**什么都不画**。
- **宿主不用改代码**:四端都在列表内部画,没有新的公开 API,signature 仍 0/0/0。两个入口(点引用、宿主 `scrollToMessage`)都会标记。
- **Reduce Motion 下不再是「没有」**:此前 Vue 的标记只以动画形式存在,而全局无障碍规则把动画压到 0.01 ms——要求减少动效的读者得到的是零反馈。现在改成静止保持中间那一档,窗口结束再消失。
- **Vue 视觉的两处变化**:关键帧改成 `linear`(原来是 `ease-out`,三个原生动画系统无法复现同一条缓动曲线),时长 1.45s → 1600ms(与摘除 class 的那个数合并成一个);同一时刻只标记一行(此前 1.6 秒内连续定位两次会同时亮两行)。

**语义色是一对，不是一个（Round 6 · B7，四端 + 文档站）**

- 每个语义色都有两个 token:**填充**(`primary` / `error` / `success` / `info` / `warning`)与**同一含义的文字色**(`primaryText` / `errorText` / …)。此前有 **477 处**用填充色画文字和图标(Vue kit 与文档站 219 处,三个原生 kit 258 处)——亮色下看不出来(品牌色与 warning 两个半边在亮色里是同一个值),暗色下是 1.58–2.98:1,远低于 4.5。现在全部改用文字色那一半,暗色下 5.06–12.51:1。
- **宿主要注意的 token 取值变更**:暗色 `error` `#EF4444` → **`#DC2626`**、暗色 `warning` `#D97706` → **`#A16207`**(白字压在这两个填充上原本是 3.76 / 3.19;改后作为强调色仍在非文字的 3:1 之上),亮色 `errorText` `#DC2626` → **`#C62828`**(它实际用在红色浅底上,原来是 4.11)。如果你直接消费这三个 token,颜色会变。
- 两处组件修正:成员角色徽章不再「白字压在 `text-tertiary` 上」(暗色 2.54:1),改为中性徽章,群主徽章自带前景色;圈子卡片的位置行不再用 `opacity: 0.8` 把已经校准过的颜色调暗到 3.78。
- **新门禁(共 40 条)**:`check-contrast-tokens` 禁止「填充色当前景」与「文字色当填充」,四端 + 文档站都查。网站的 a11y sweep 现在每个预览前钉死主题,并且桌面端**亮暗各扫一遍**(298 次扫描,0 critical / 0 serious)。

**「翻页直到找到那条消息」下沉进 kit（Round 6 · B8，四端）**

- 新增 `flareLocateMessage`(Vue / Flutter / Compose)与 `FlareLocate.run`(SwiftUI):先问列表 → 翻一页历史 → 让列表画一遍 → 再问,最多 **24** 页;历史翻尽后再问 **6** 次(最后一页的行可能还没画出来);结局是 `shown` / `notInHistory` / `cancelled`。规则表是 `spec/locate-orchestration-vectors.json`(13 条脚本化 run,连「问了几次、翻了几页」一起对)。

- **五个示例应用各自那份循环全部删除**(web `host/locateMessage.ts`、Tauri 的 48 页循环、Flutter 的 `revealMessage`、iOS 的 `QuoteLocate`、Android 写在页面里的 `while`)。此前五份的翻页上限是 **48 / 48 / 24 / 20 / 5**:同一条消息在网页上能跳到,在 iOS 上翻 5 页就判「不在历史里」。
- 如果你也在应用层写过这个循环,删掉它改用 kit 的——`check-ui-reuse` 现在要求五个聊天页都出现这次调用。

**表情包消息的一句话摘要（Round 6 · B9，三个原生 kit + 三个应用）**

- 一条表情包消息在会话行、回复条里现在读作**当前语言的短名**(一百分),而不是 `hundred_points`;正文里的 `[pack_key]` token 也一样(`localizePackKeysInText`)。三个 kit 早就带着这份名字表和查表函数(`emojiLabel`),只是摘要没调用。

**输入中、在线状态、漫游草稿（Round 7，四个 kit）**

- **新增规则模块**：`FlareTypingSignal`（我在打字：空闲 4000ms 停、最多每 2500ms 重发一次 true）与 `FlareTypingRoster`（对端在打字：一条信念 6000ms 过期，服务端名单整条替换，收到某人消息即停）；`flareTypingNames` 给未认出的人一个称呼而不是原始 id。两半在**同一张表** `spec/typing-vectors.json` 里，因为 `refreshMs < peerTtlMs` 只有放在一起才断言得了。
- **新增规则模块**：`FlareDraftAutosave` 与 `flareRestoredDraft`（`spec/draft-vectors.json`）。草稿停手 1200ms 写一次、**离开立刻写**、发送时取消待写并清空、与已存内容相同的不写；发送失败的原文立刻写回，不走防抖。
- **新增组件参数**：SwiftUI `ComposerView` 与 Compose `Composer` 的 `onUserInput`（只报人自己的编辑，组件发送后的清空不算）；三个原生 `MessageList` 的 `footer` 槽（契约早就声明了，实现一直没有）；Flutter / SwiftUI `ConversationRowData.hostFacts(draftPreview:typing:presence:)`。

**壳层契约 v2（Round 9 · B2–B4，四个 kit，破坏性，无别名）**

- **`IMAppKit` 量自己的盒子**（宽度与文字缩放）得出手机 / 平板 / 桌面，并把模式放进上下文（Vue provide、Flutter `FlareShellScope`、SwiftUI Environment、Compose CompositionLocal）。删掉的参数：`responsiveMode`、`primary`、`detail`、`hasDetail`、`activePane`、`paneMode`、`detailMode`、`hideMobileNavigation`、`onLayoutChange`。宿主不要再监听窗口宽度。
- **按导航 id 渲染目的地**：Vue 作用域插槽 `destination`（`{ id, active }`）、Flutter `destinationBuilder(context, id)`、SwiftUI `destination: (String) -> AnyView`、Compose `destination: @Composable (String) -> Unit`。访问过的目的地常驻（滚动位置与状态保留）；导航项消失的目的地被丢弃。宿主不要再自己 `KeepAlive` / `ZStack` 常驻。
- **窗格框架删 `responsiveMode`**：`AppLayout`、`WorkspaceFrame` 在壳层里用壳层的模式，壳层外自己量；`DesktopAppShell` 保留自己的参数。`AppLayout` 放进手机壳后恒为单栏。
- **手机底栏由深度决定**：每个目的地一份深度登记。`FlareScreen` 带返回、窗格框架单栏且显示的不是根窗格时自动登记；宿主自绘的二级页用 Vue `useFlareDestinationDepth(active)`、Flutter `FlareDestinationDepth`、SwiftUI `.flareDestinationDepth(_:)`、Compose `FlareDestinationDepth(active)`。活动目的地深度 > 0 时手机收起底栏；平板 / 桌面的轨道与侧栏不受影响。删掉宿主自己的底栏布尔式。SwiftUI 另有 `flareDestinationActive` 与 `flareDestinationPresentation`（给用平台容器分栏的目的地）。
- **Flutter 宽屏壳自带 Material 地面与安全区**：宿主不要再包 `Scaffold`。
- **视觉变化**：手机壳只在宿主给了 app bar 时画 app bar，每个手机页面顶部那条 1px 空横线消失（FR-137）；目的地隐藏时关闭自身与后代的过渡，减弱动效下不再闪一帧旧页面（FR-138）。常驻的目的地仍在 DOM 里：测试里的文本定位器请加可见性过滤。
