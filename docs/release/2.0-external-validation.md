# 2.0 External Validation

需要本机之外的环境（真机、Linux CI、发布负责人决定），或本机有环境但本轮未执行的验收项。每个包（packet）都给出：Requirement ID、设备、OS、前置、构建 / 运行命令、步骤、PASS 条件、证据格式、产物位置、Candidate ID。需求图是 `spec/release-requirements.json`，逐条状态以 `artifacts/release-2.0/evidence-manifest.json` 为准。

> 本文件只描述**如何取得证据**，不替代证据。一个包没执行完之前，对应需求保持 `NOT_RUN` / `BLOCKED_EXTERNAL_ENV`。

## 0. 所有包的共同规则

- **Candidate ID**：执行前读 `artifacts/release-2.0/candidate.json` 的 `candidateId`，或运行 `node tooling/release-candidate-id.mjs`；结果文件必须写同一个值。候选变了（任何源码、测试、token、基线、判据变化）旧结果即 `STALE`，必须重做。
- **构建来源**：设备上安装的 app 必须从该候选的工作树构建；记录构建命令与产物哈希。
- **证据格式**：JSON，字段见 [2.0-manual-evidence-checklist.md](2.0-manual-evidence-checklist.md) §4（`requirementId`、`candidateId`、`level`、`result`、`device`、`os`、`build`、`steps[]`、`evidenceUris[]`、`tester`、`date`）。
- **产物位置**：`artifacts/release-2.0/native/<ID>.json`（原生运行时 / 权限 / 生命周期 / 安全区 / IME）、`artifacts/release-2.0/accessibility/<ID>.json`、`artifacts/release-2.0/performance/<ID>.json`；属于 `spec/manual-evidence.json` 的 13 条，另把该条改为 `"status": "PASS", "evidence": "<路径>"`。
- **禁止**：模拟器结果写进真机要求的条目；录屏 / 日志里出现密码或 token；只跑一部分步骤就写 PASS。
- **测试账号**：只用 `ui2-release-*`。

## 1. 本地联调环境（Web live、原生运行时共用）

### 1.1 服务端（core profile，联调签发）

`POST /api/v1/auth/tokens` 需要业务后端带 `x-app-id` / `x-app-secret`，或网关开 `FLARE_API_GATEWAY_AUTH_DEV_ISSUE`（联调，默认关）。web 示例与原生示例的登录页都走后者。详见 `flare-im-core/docs/AUTH-TOKEN-ISSUANCE.md`。

> ⚠️ `AUTH_DEV_ISSUE` 允许任何人冒充任意用户，**仅限本地 / 联调**。还原：`cd flare-im-core && ./scripts/start_server.sh`，或去掉该环境变量重起网关。

```bash
cd /Users/hg/workspace/flare/flare-im/flare-im-core
PR=$(pwd)
# 坑 1：BSD sed 不支持 \s，用 [[:space:]] 或直接 tr -dc '0-9'
p(){ grep -E '^[[:space:]]*port[[:space:]]*=' "config/services/$1.toml" | head -1 | tr -dc '0-9'; }
# 坑 2：缺 FLARE_API_GATEWAY_TOKEN_SECRET 时网关以 ConfigurationError 退出；
#       start_server.sh 从 logs/.dev-token-secret 导出它，单独起网关必须自己补上。
SECRET="$(cat logs/.dev-token-secret)"
kill "$(cat logs/flare-api-gateway.pid)" 2>/dev/null; sleep 3
export FLARE_API_GATEWAY_TOKEN_SECRET="$SECRET" ACCESS_GATEWAY_TOKEN_SECRET="$SECRET" FLARE_ADMIN_GATEWAY_TOKEN_SECRET="$SECRET"
export NO_PROXY="localhost,127.0.0.1,::1" no_proxy="localhost,127.0.0.1,::1"
export CONSUL_DISCOVERY_REFRESH_INTERVAL=90 CONSUL_DISCOVER_CACHE_TTL_SECS=15 SERVICE_HEARTBEAT_INTERVAL=30
export FLARE_API_GATEWAY_GRPC_MESSAGE_INGEST_STATIC_FALLBACK="http://127.0.0.1:$(p message-ingest)"
export FLARE_API_GATEWAY_GRPC_MESSAGE_ORCHESTRATOR_STATIC_FALLBACK="http://127.0.0.1:$(p message-orchestrator)"
export FLARE_API_GATEWAY_GRPC_CONVERSATION_STATIC_FALLBACK="http://127.0.0.1:$(p conversation)"
export FLARE_API_GATEWAY_GRPC_MEDIA_STATIC_FALLBACK="http://127.0.0.1:$(p media)"
export FLARE_API_GATEWAY_AUTH_DEV_ISSUE=true
nohup "$PR/../target/debug/flare-api-gateway" >> logs/flare-api-gateway.log 2>&1 &
echo $! > logs/flare-api-gateway.pid
```

`start_server.sh` 吞错并以 0 退出，所以起完必须独立探活：

```bash
curl -s -X POST http://127.0.0.1:50050/api/v1/auth/tokens \
  -H 'Content-Type: application/json' \
  -d '{"userId":"ui2-release-desktop","tenantId":"0"}'
```

应返回 `"code":0`（输出里有 token，不要贴进任何证据）。

### 1.2 web app 与 dev token secret

web app `.env` 的 `VITE_FLARE_TOKEN_SECRET` 需与服务端 `logs/.dev-token-secret` 一致（只按哈希比对，不打印）。用 gitignored 的 `.env.local` 对齐：

```bash
APP=/Users/hg/workspace/flare/flare-im/flare-im-core-client-sdk/examples/flare-core-web-app
printf 'VITE_FLARE_TOKEN_SECRET=%s\n' \
  "$(tr -d ' \n\r' < /Users/hg/workspace/flare/flare-im/flare-im-core/logs/.dev-token-secret)" \
  > "$APP/.env.local"
cd "$APP" && npm run dev:web -- --host 127.0.0.1 --port 1430 --strictPort
```

生产构建的 WS / HTTP 端点为空（部署注入），对接本地后端要用 dev server。

### 1.3 Final Validation（REL-VALIDATION-A / REL-VALIDATION-B / LIVE-WEB-SDK）

冻结后连续两轮，中间不写仓库：

```bash
cd /Users/hg/workspace/flare/flare-im/flare-im-design
for RUN in final-A final-B; do
  FLARE_RELEASE_RUN_LABEL=$RUN FLARE_ALLOW_LIVE_SEND=1 \
  FLARE_LIVE_BASE_URL=http://127.0.0.1:1430 \
  FLARE_LIVE_USER=ui2-release-desktop FLARE_LIVE_PEER=ui2-release-mobile \
  npm run release:check || break
done
node tooling/check-release-evidence.mjs
```

产物：`artifacts/release-2.0/automation/runs/<RUN>/{report.json,report.md,candidate.json,<gate>.log}`；最后一轮镜像到 `automation/report.*`、`live-sdk/`、`package/`、`security/`。PASS：每个 gate PASS，`candidateIdAfter == candidateId`。

## 6. REL-UNSUPPORTED-SCOPE（发布负责人决定）

`share`（Tauri / Flutter / iOS / Android）与 `nativeBack`（全部宿主）在 2.0 候选里是 UNSUPPORTED，入口按 [platform-fallback-policy.md](platform-fallback-policy.md) 隐藏。上一版最终报告把 stable 设为"实现它们，或由负责人明确接受本版不提供"。决定写入 `artifacts/release-2.0/signoff.json`：

```json
{ "candidateId": "<candidateId>", "result": "PASS", "unsupportedCapabilitiesAccepted": true,
  "capabilities": ["share", "nativeBack"], "owner": "<name>", "date": "<YYYY-MM-DD>", "note": "<why acceptable for 2.0.0>" }
```

拒绝则写 `"result": "FAIL"`，该需求保持未销，实现后重新认证。
