# 2.0 Final Closure Plan（Final Release Certification）

候选：`2.0.0-rc.1`，候选身份见 `artifacts/release-2.0/candidate.json`。本文件是认证阶段的执行计划与需求台账的人读视图，不是发布证书。机器可读的真源是 `spec/release-requirements.json`；逐条判定由 `node tooling/check-release-evidence.mjs` 写入 `artifacts/release-2.0/evidence-manifest.json`，本文件的「Status at freeze」列是冻结时的状态，冻结之后的结果只看 manifest（本文件属于台账，冻结后不再改）。

结论只有两种：READY 或 NOT READY。

## 0. 原则与禁止事项

Stability > Elegance；Evidence > Assumption；Reproducibility > One-time Pass；Real Environment > Mock；Candidate Integrity > Convenience。只有 Release Gate 暴露真实缺陷时才改生产代码。

禁止：为了 READY 修改判据；把 manual P0 改成 P1；mock live backend；伪造原生证据；模拟器冒充真机；axe 代替 VoiceOver / TalkBack；build PASS 代替 runtime PASS；截图 PASS 代替交互 PASS；skip flaky；重跑到偶然变绿；放宽断言解决竞态；release chain 运行中改仓库；冻结后改 tracked files；用旧候选的证据证明新候选；手改 report.json。

## 1. READY 的判定

两层，必须同时满足：

1. **发布策略**（`tooling/release-policy.mjs`，release:check 的 `ready`）：非诊断运行 ∧ 结果数 = 期望数 ∧ 每个 gate PASS ∧ `spec/manual-evidence.json` 无未销条目 ∧ `docs/2.0-readiness-matrix.md` 无阻塞行。
2. **认证需求图**（`spec/release-requirements.json`）：每个 P0 需求 `PASS` 且依赖全部 `PASS`。需求图覆盖发布策略的全部内容，再加上发布判据（`2.0-release-criteria.md`）里没有 gate 实现的行、认证简报要求的原生运行时 / 权限 / 生命周期 / 安全区 / IME / Linux 视觉 / 包认证 / 安全。

## 2. 候选与证据有效性

- `candidateId = flare-im-design@<vue-ui 版本>+<16 hex>`：对设计仓、client SDK、五个示例的文件内容求哈希（`git ls-files --cached --others --exclude-standard`），**不含**发布台账（manual-evidence、readiness matrix、inventory、final report、本计划、external validation、manual evidence checklist、support matrix、gap analysis），另外绑定 publicApi / tokens / snapshots / releaseCriteria / componentContracts 五个指纹与三个版本号。记录一条设备结果不会让证据自己过期。
- `sourceFingerprint`：release:check 的 `candidate-integrity` 用的全量指纹（含台账），证明一次运行过程中仓库没被改动。
- 每个证据文件都写 `candidateId`。与当前候选不一致即 `STALE`，不是 PASS。
- `artifacts/` 在 `.gitignore` 里，被候选指纹与 inventory 排除，被 `check-repository-scope` 允许。
- 状态只有 `PASS` / `FAIL` / `NOT_RUN` / `BLOCKED_EXTERNAL_ENV` / `STALE`。
