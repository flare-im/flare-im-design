# 2.0 Release Criteria

本文件定义 flare-im-design 2.0.0 的发布门禁：每一条都是可执行的检查或可复核的产物，不接受「看起来完成」。任何一条 P0 未 PASS，版本号保持 `2.0.0-rc.*`。

## 2. 组件准入标准（每个 public component）

| 条件 | 证据 |
|---|---|
| 在 spec/component-catalog.json 登记，有 Purpose / When to use / When not to use | docs/components/component-catalog.md |
| Maturity 为 STABLE / BETA / EXPERIMENTAL / DEPRECATED；STABLE 必须有真实消费者（example 或 flare-social）+ 组件测试 + a11y 契约 + 文档 | docs/components/component-maturity.md |
| 四端 symbol 存在且 public（或契约登记为平台差异） | check-public-exports |
| 不直接依赖 SDK 网络、DB、路由、存储；平台差异经 PlatformCapabilities | 代码审查 + design-source-check |
| Controlled/Uncontrolled 明确（overlay/composer/selection） | 文档 + 测试 |
| 没有 boolean explosion（≥8 个 boolean props 需说明） | inventory props 统计 |

不满足 → INTERNALIZE / MERGE / DEPRECATE / REMOVE（见 component-architecture-audit.md）。

## 3. Example parity（docs/release/example-parity.md）

每格只能是 PASS_RUNTIME / PASS_TEST / PASS_BUILD / SIMULATED / UNSUPPORTED / FAIL。Web（flare-core-web-app + shared/vue-reference）为 Golden Reference；Tauri/iOS/Android/Flutter 与之对照。至少覆盖：登录、会话列表、打开会话、收发文本、图片/文件发送、已读、置顶、撤回、@ 提及、长按/右键菜单、来电、离线/重连、暗色、断点、安全区、原生能力（文件/图片/相机/分享/剪贴板/返回）。UNSUPPORTED 必须对应 platform-fallback-policy.md 里的条目。

## 4. P0 / P1 / P2 定义（Change Budget）

- P0：阻断主任务、危险、关键动作不可达、架构缺口（平台契约、重复公开面、边界）、可达性 Critical/Serious、安全边界、无证据的发布声明。必须修。
- P1：明显降低长期维护成本且风险低（几何统一、token 化、契约 prop 对齐、文档噪音）。可修。
- P2：命名洁癖、装饰性清理、面向未来假设的抽象。rc 阶段不做。

## 5. 版本策略

| 条件 | 版本 |
|---|---|
| 任一 P0 未 PASS | 保持 2.0.0-rc.1 |
| P0 全部落地且有证据，仅剩真机 MANUAL 项 | 2.0.0-rc.2 |
| §1 全部 PASS + MANUAL 项完成 + Final Report = READY | 2.0.0 |

版本号只在 release:check 全绿后修改，随后必须重跑一次全量。

## 6. 禁止事项（自动化必须能抓）

- 删除失败测试、降低断言、skip/todo、mock success、fake native result（stub-check + 测试计数不得下降）
- 为通过测试改基线而不标 EXPECTED/REGRESSION
- Example 自绘 kit 已有组件（design-source-check）
- 在组件里散落 if mobile/desktop/ios/android/tauri（capability lint）
- 未登记的公开导出（api-check）
