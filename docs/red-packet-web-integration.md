# Web 红包使用共享 Kit 设计

消息卡片、发送页、开红包和详情分别使用 `FlareRedPacketCard`、`FlareRedPacketComposer`、
`FlareRedPacketOpenSheet`、`FlareRedPacketDetail`。不复制这些组件的样式或在应用覆盖内部结构。
Vue 与 Flutter 发送组件的主按钮均使用 md 规格，Flutter 保留最小触控区域；Vue 分段选择器支持
方向键、Home/End、焦点环及移动触控尺寸。发送内容列限宽使用共享 tokens。

Web 宿主在插件页面的 `content` 插槽组合这些组件，只映射已解析的服务数据、允许的类型、
精确金额、授权成员、角色、姓名及头像，不执行资金操作。付款和领取仍进入原 Core 插件会话。
`contentActionIds` 明确哪些可见根动作由自定义组件负责；密码、原生、确认及其余动作仍由
Kit PluginView 执行保护和表单流程。内容回调不能覆盖页面、数据和记录绑定，刷新时不可提交。

发送与领取采用一致的信息层级：

- 分段选择类型，金额与份数同排输入，祝福语独立，总额居中。
- Vue / Flutter 发送页使用简洁的主题表面，移除整块红底、渐变、金色装饰和重复祝福，顶部使用共享 72px 红色弧形头部。总额为 24px 中性文字；红色仅用于类型选中态和标准 md 主按钮。输入区域、焦点、错误和禁用态遵循明暗主题。
- 单聊无需选择类型或填写份数；专属红包使用授权成员选择器，按昵称/账号的宿主搜索选择。
- 聊天消息列表和红包卡片的尺寸、布局、间距、图标保持原样；仅把未领取 / 可查看状态改成 redPacket.end 深红底与白字，已领取 / 已领完及其他终态保持原 faded 浅红底与深字。四端组件同步这条配色规则。
- 发送页和详情顶部使用 72px 纯红色弧形，不承载文字。详情本人金额 32px，到账提示带成功图标，摘要与记录分层；长姓名和长金额在窄屏各自保持可读，导航栏中性。
- 领取弹窗保留原有红色信封、金色「開」与交互状态，本轮不改。
- 详情显示发送人、祝福语、当前用户可见金额、领取记录及服务端的手气标记，不推算隐藏金额。

钱包余额/支付确认与实名状态/材料上传继续使用对应的 Kit 组件与服务声明。对照 Flutter 的
账户、红包和实名布局，保留金额、状态、材料、记录的主次关系；未恢复旧版本的业务 renderer。
无能力/无付款通道、首次加载、刷新失败和升级提示仍由插件页面处理，不用空白页掩盖错误。
取消、失败或刷新不会自动付款；只有明确的用户动作可以触发原命令和受保护支付确认。

本轮 Web 与 Flutter 共享组件仅同步发送页与详情视觉；消息列表布局、红包卡片几何和领取弹窗保持原样，卡片只同步配色。SwiftUI / Compose 卡片同步同一配色规则，弹窗和详情仍保留原视觉；已核对其参数、状态和查看资格契约，本轮未运行其原生设备界面。

## 表单可用性与键盘

Web 分段选择器对长语言标签换行，保持等宽选项、完整可访问名称与键盘焦点；不让第三项挤出 320px 屏幕或窄侧栏。

四端发送组件在 `kinds` 为空时锁定输入与提交；宿主使用现有状态提示说明不可用原因，不能让未授权类型继续提交。`busy` 表示正在处理，`locked` 表示等待结果确认，两者均不开放重复提交。

Web 的金额、份数和祝福语支持 Enter 提交，仍经过同一个提交事件与可用性校验。中文、日文输入法的组词确认不触发提交；兼容浏览器的 composition 与 229 键码。错误提示通过 `aria-describedby` 关联表单组并使用 alert 宣读；输入值和既有聊天消息布局不受影响。

这些能力属于共享 Kit 的交互契约；应用继续负责余额、金额上下限、成员授权和真实支付结果，不在组件内实现业务规则。

## 领取结果待确认

Vue `FlareRedPacketOpenSheet` 的 `reviewOnError` 默认关闭。宿主仅在能提供只读详情刷新时开启，且仍需 `canViewDetails` 授权；错误态出现“查看领取详情”后，`view-details` 只能读取结果，不能隐式再次领取。原有关闭与手动操作保持不变。Flutter、Android 和 iOS 目前未实现这个新增参数，其宿主仍应遵守相同的只读恢复语义。
