# 钱包、支付确认与材料上传 · Web 对齐

Web 的钱包入口由宿主明确选择 `account` 外观。对于 vocabulary 2 的钱包文档，Kit 将单个
可遮罩金额区和钱包记录组合到现有 `FlareAccountView`：PC 使用卡片网格，手机单列，余额遮罩
作用于所有钱包。金额、币种和记录保持独立，不计算多币种总额。原始 rows、row key、action input
及确认 / 密码 / 原生动作仍经过原管线；缺少明确钱包结构时继续使用声明式文档，不凭标签猜业务。
这复用 Flutter 的钱包卡片与服务分组设计，不恢复服务端旧业务 renderer。

`FlarePaymentConfirmation` 在 Vue / Flutter 使用 md 按钮与可展开订单号，突出金额、收款方和
用途。Vue 的操作区随内容滚动保持可达；服务器时钟、无效金额、宿主凭证门槛与忙碌锁继续生效。
打开时已经过期的订单也只通知一次，换订单后独立计算过期状态。组件不保存支付密码或自动重试付款。

材料只由宿主选择、处理与上传。Vue 纯材料表单在宽屏并排、窄屏单列；上传状态与错误通过读屏状态
关联到选择按钮。Vue / Flutter 的证件拍摄组件从相册选择开始锁定重复操作；选择取消回到取景状态，
异常可重新选择，切面 / 关闭 / 卸载后的旧结果不再填入新材料。确认、重拍和相册按钮使用 md。

材料是否必需、是否要求手持由服务配置决定。失败重试保持原文件和上传命令标识；未上传完成时不提交
材料表单。审核未通过、提交结果未知与上传失败分别使用服务声明的原因、原操作恢复及文件重试入口。
私密材料仍由本人或具备审核权限的员工按需获取，不把受保护地址写进公开页面数据。

本轮优先实现并验收 Web；Flutter 同步支付和证件拍摄行为与按钮规格。SwiftUI / Compose 的相应
组件已纳入规格检查，本轮未进行其设备运行验收。

Social Vue 的错误文案优先匹配服务提供的支付密码 machineReason，再回退到通用插件拒绝；不显示原始
服务错误或凭证内容。Web 能力确认面按需读取当前语言的账户服务名称，避免仅因未打开个人中心而缺失名称。
