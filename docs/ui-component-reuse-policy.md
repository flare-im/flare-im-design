# UI 组件复用规则

适用于 `flare-im-core-client-sdk/examples/**`、`flare-social/flare-social-sdk/examples/apps/**` 以及 `flare-im-design/**` 的 UI 工作。

- UI 的唯一设计来源是 `flare-im-design`。先查对应平台已有组件、组合组件和 tokens，再开始实现。
- 已有组件可满足需求时直接复用，不在 app 内重新实现输入框、按钮、空态、状态条、弹窗、消息气泡等通用 UI；不要复制组件源码或用应用样式覆盖其内部结构。
- 已有组件缺少通用能力时，在设计库补充属性、插槽、状态或对应平台实现，并补充文档与适当验证；不要留一份仅某个示例应用可用的变体。
- 应用可以组合共享组件并实现路由、SDK 回调、业务校验、权限数据映射和业务专属流程。不要为了复用视觉组件把 SDK 或产品业务规则塞进设计库。
- 页面布局使用共享布局组件和 tokens；确实需要局部布局代码时，只写业务组合所需布局，不另建颜色、字号、圆角、图标、阴影体系。
- 原生文件选择器、系统权限弹窗和系统键盘保留平台适配；一致性指组件语义、状态、视觉层级与交互规则一致，不强制所有平台使用同一渲染框架。
- 同类变更检查 Web/Tauri、SwiftUI、Compose、Flutter 对应实现；一起考虑明暗主题、国际化、无障碍、触控区、桌面键盘、加载/空/错/禁用状态。
- 迁移后删除失去用途的自绘组件和样式。业务适配器只做数据映射/组合，不允许继续持有重复视觉实现。
- 现有遗留页面逐步收敛，不把“已接入组件库”当作“所有页面已完成统一”的证据。报告实际替换范围与未验证项。
