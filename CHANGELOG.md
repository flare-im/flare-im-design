# Changelog

## 2.0.0 (Unreleased, Release Blocked)

This is the target Stable release, not a published version. Package metadata remains 2.0.0-rc.1 until every release gate and required review passes.

### Design System And Packages

- InviteCodeField (Form) and MyInvitePanel (Profile), one contract on four platforms (`spec/components.json`, vectors in `spec/invite-vectors.json`): tenant-mode invite-code entry with server-style normalization (O→0, I/L→1), debounced host pre-check and deep-link prefill; the "my invite" card with copy / share / regenerate cooldown, referral depth counts, count-only mode and a keyset invitee list. `Input` gains `monospace` on every platform. Strings: `inviteCode*` / `myInvite*` in the four strings providers.
- **`FlareSearchPanel` can be the whole search page** (Vue). `layout="page"` is two rows of which only the second scrolls: the field and the type row stay still over a hairline, the results scroll under it in the panel's own body (a new query's results start at the top), the panel owns the page gutter and the safe areas, and result rows run edge to edge (rows, group labels and the more row take the gutter through `--flare-search-gutter`; inline panels are unchanged). It is not `position: sticky`: a sticky head has to paint a ground of its own, jumps by the host's padding when scrolling starts, and leaves the scroll position to a host that cannot know a new query arrived. `requireQuery` makes a type or a time range alone rest idle — for a search across kinds, where "every contact" is the contact list's job. A host that listens for `cancel` gets the search bar's own way out beside the field; the panel forwards the listener only then, so a panel inside a page with a back button does not grow a second exit. The `idle` slot is handed `search(term)` to search for a term at once. `snapshot.warning` is said above results that came back incomplete, with a retry. The props, the event and the slot are scoped to Vue in the contract, each with its reason.
- `FlareFilterTabs size="sm"` really is hit at 48px. The row is its own scroll container (`overflow-x: auto` makes `overflow-y` compute to `auto` as well), so the part of each tab's `::after` hit area that reached outside the 36px row was clipped above and became 6px of vertical scroll below: the target was 36px and the row could be dragged up and down. The row now gives the hit area its height in padding and takes it back with a negative margin (layout unchanged), and the hit area is also at least 48px wide. `website/tests/search-page.spec.ts` probes the four corners of every type and the row's vertical scroll; the unit test only ever asserted class names.
- `FlareSearchPanel` (Vue) follow-ups from review: cancelling drops the panel's own pending search, so no `search` arrives after the host was told the user left; a host reset to idle also clears words that were typed but never submitted and a type that was only chosen; picking a recent search puts the caret back in the field before the idle slot is removed (focus used to fall to `<body>`, where a page's Escape handler no longer heard the key) and the `idle` slot is also handed `focusField()`; a recent search that failed is no longer silently retried when the typing pause ends. `FlareSearchBar` exposes `focus()` and searches once per committed composition whatever order the engine reports it in (Safari and Firefox send `compositionend` before the last `input`).
- `tooling/check-token-fallbacks.mjs` rejects `-var(…)`. It is not a negated `var()`: CSS reads an unknown function named `-var` and drops the whole declaration, and a mechanical swap of `-10px` for `-var(--flare-size-spacing-2sm)` had silently removed `FlareScreen`'s back-button offset (and a margin in `chat/messages.css`) while the raw-value gate counted it as an improvement. Both now use `calc(-1 * var(…))`.
- Flutter `FlareRichTextMessage` loads the emoji catalog for a document whose only emoji are `[key]` tokens in text runs. The load was triggered by `emoji` runs alone, so with a cold catalog — the state an app opens a conversation in — the tokens stayed words; the widget test had preloaded the process-wide catalog and hid it. `test/rich_text_message_cold_catalog_test.dart` is its own isolate and never preloads. SwiftUI names the inline emoji images for VoiceOver (the run's text, or `[key]` for a token).
- **A truncated result group no longer needs a count** (four platforms). `FlareSearchResultGroup.hasMore` draws a countless "查看更多 / See more" row ("更多" on the native kits, their existing `more` string) for a search API that takes a limit and returns no total — ask for one more than is shown. `total` still wins and a count is never made up; until now the "查看全部 N 条" row could not appear for any host whose backend returns no totals. When a group's kind is also one of the panel's type ids, the Vue panel switches to that type itself (the type is its own state, a host could not) and still reports `viewAll`.
- New `FlareRecentSearches` (Vue): the terms used last as full-width rows (a clock glyph and the term — rows, not capsules, because on a search page they sit right under the type row, which already is a row of capsules that mean something else), one tap from searching again, with one way to forget them all. A row is its own 48px hit area. Nothing is drawn without items, so the page's idle line shows instead. The host owns the list; `flareRememberSearch(list, term, max)` on `./contracts` is the shared rule for keeping it (trimmed, newest first, a repeat moves to the front).
- `FlareSearchBar` (Vue) never searches for an IME's half-typed text: the model still follows every keystroke, the debounced `search` waits for `compositionend`. Hosts that use the bar directly (add friend, join group, start chat) were searching for unfinished pinyin after the pause; `FlareSearchPanel` had its own guard, the bar had none.
- **A rich-text body draws the `[key]` emoji-pack tokens in its text runs** (four platforms). The core's Markdown normaliser stores the token the composer writes as literal text, never as an `emoji` run, so the emoji a plain message draws read as `[angry_face]` once the same message was sent as rich text — on every client. A text run now splits at the tokens the catalog knows and draws them inline at the size an `emoji` run has (Vue `FlareRichDocRuns`, Compose `flareRichRunsText` + `flareRichEmojiKeys`, SwiftUI `RichTextMessageView.inlineEmojiParts`, Flutter `_run`), keeping the run's marks and link; unknown keys, inline code and covered spoilers stay the words they are. The model and `spec/rich-doc-vectors.json` outlines are unchanged: this is how a text run is drawn, not how a document is read. The upstream half is proposal S28 in `docs/product/sdk-change-proposals.md`.
- `FlareScreen` (Vue) draws its back button only when asked. The handler added for contextual layers was a `<script setup>` function named `back`, which shadows the `back` prop in the template, so `v-if="back"` was always true and every screen — the tab roots included — grew a back arrow that did nothing. The handler is `goBack`; `FlareScreen.test.ts` mounts a screen without `back` and expects no button.
- **Timeline avatar: one token, one size, top-aligned** (four platforms). New `sizes.component.messageAvatarSize` = 40px; the three native kits replace their literal 34 with it, Vue drops its 34/36 container-query split and the four magic offsets (16/24/17/25) that bottom-aligned a 34px avatar to a one-line bubble. The avatar's top now equals the row's content top (the run gap, `spacing.sm`) like the natives: on a plain row it is flush with the bubble's top and bottom (40 = a one-line bubble), on a row with a sender-name line it aligns with the name. The avatar gutter is `avatar + spacing.sm` (48) at every width; the run gap goes from a literal 9px to `spacing.sm`. Contract slot `MessageRow.avatarSize` holds all four to the token.
- Composer (Vue): the rich-text format strip is one flat row on the input's own surface — the older global strip design in `chat/messages.css` (gradient card, hover glow, seven `color-mix` locals, 28/30px keys) fought the component's styles and is deleted; the component owns the strip. On coarse pointers keys draw 36px with a 44px hit area (the old `flex-basis` pinned them to 28px under the 44px floor); the strip is 36px (was 44) on the input's own surface, separated from it by a full-width 1px hairline. The text-style picker is no longer a native `<select>`: on a coarse pointer the trigger expands in place into a P/H1–H6 row (no overlay, the editor keeps focus and the soft keyboard stays), elsewhere it opens the kit's anchored menu above the trigger; keys, picker and group dividers all follow the platform's one pointer signal (`data-pointer`), and touch strips use spacing instead of dividers so no line is cut at the scroll edge. Picking from the anchored menu no longer closes an open composer panel (the composer's outside-pointer rule treated the teleported menu as "elsewhere"). Tool-row keys read the `composerActionHeight` token (40) instead of a hard 44, with a 44px hit area, and no longer paint a hover/active fill — on touch, `:hover` stuck to the last key as a grey square. The send key is the quiet paper plane again (an uncommitted filled-primary variant was withdrawn).
- **`FlareMessageBatchToolbar` owns leaving multi-select** (Vue): while it is mounted with an `@exit` listener it is a *contextual layer* — Escape (on `window`, bubble phase), the platform back and the first press of a kit back control (`FlareConversationHeader`, `FlareScreen`, `FlareResponsiveLayout`) all emit `exit`; while `busy` they are consumed and nothing exits. Escape is left alone when a modal surface or a visible `aria-modal` dialog is on top, when an editable control has focus (its own Escape comes first, so from the composer it is two presses), when the focused element sits on a page that does not contain the toolbar, when the key was already `preventDefault`ed, and during IME composition. Hosts delete their own Escape/back glue: the web reference app had three pieces, the Tauri one had none. New internal rule module `shared/useContextualLayer.ts` (not exported); `claimNativeBack` handlers may return `false` to decline. Escape consumers in the kit now claim the key they use (`FlareSelect`, `FlareDatePicker`, `FlareTimePicker` popovers, `FlareConversationRow` menus) — a layer that closes on Escape without `preventDefault` would otherwise also exit a selection underneath it.
- `FlareMessageBatchToolbar` layout: the non-floating bar wraps its keys at every width, as the three native kits do — the ≤599px rule that turned it into a horizontal strip with a hidden scrollbar and the exit key last is gone, which is what scrolled the exit out of view on a phone. Only the floating bar (it cannot grow over the timeline) still scrolls; there the exit key is pinned to the end on an opaque ground, keys focused by Tab stop short of it (`scroll-padding-inline-end`), and an end fade appears only while keys are actually hidden behind it. The count announces politely.
- **The message bubble is drawn by its surface, not by an outline** (four platforms). The incoming bubble used to be the same colour as the surface behind it — `#FFFFFF` on `#FFFFFF` in light, `#20232B` on `#20232B` in dark, **1.00:1** both ways — so its 1px hairline was not decoration but the bubble's only edge, and the solid group-end tail painted straight over it and left a notch at the corner. `colors.message.incoming.background` is now a tertiary surface (`#F1F2F5` light, `#292D37` dark) and the hairline is gone from the incoming and outgoing bubbles on Vue, SwiftUI, Compose and Flutter; the three native kits never stroked the outgoing bubble, so this also ends a four-platform split. The failed state keeps its red outline — there it carries meaning. On the web the outline comes back under `forced-colors: active` (the mode replaces author backgrounds outright, so a surface difference would render as nothing) and under `prefers-contrast: more`; both are web-only modes, which is why the native kits need no counterpart. A host that themed `message.incoming.background` to match its own canvas should re-check it.
- `colors.avatarTint.pink.fg` (light) `#BE185D` → `#9D174D`: the four-platform unification of the identity palette had settled on the three native kits' value, which reads at 4.37:1 on the pink surface; the Vue kit had already moved to `#9D174D` (5.70:1) for that reason, and the migration note said so. Base dark `primaryText` `#A78BFA` → `#C4B5FD`: every brand's dark text tint was already one step lighter, and the base value was the only one whose selected reaction chip fell under 4.5:1 on the timeline canvas. The docs home showcase reads the identity palette from the kit's component tokens instead of a copy that had drifted and had no dark set.
- `--flare-component-chat-window-bg` gets a consumer: the timeline (`.message-list-root`) paints its own canvas, defaulting to the surface `FlareAppLayout` uses. The token was declared and used by nobody, so the timeline was transparent and the bubble's contrast depended on whatever the host happened to lay underneath — the same bubble read at 1.12:1 in the app and 1.05:1 in the docs. A host that wants a chat wallpaper sets the token instead of reaching into the timeline's class.
- **Breaking (enum): `FlareButtonVariant` gains `quiet`** on all four platforms. It is the neutral low-emphasis rung — transparent, borderless, secondary label, padding from the size class — for the exit that sits beside a primary action; `text` is branded and two violet buttons have no hierarchy. Downstream exhaustive `switch` / `when` over the enum must handle the new member. The three native kits previously worked around its absence with Material `OutlinedButton` (Compose, Flutter) and `.secondary` (iOS), so the friend-request row rendered four different ways; all three now use the rung.
- `spec/validate.mjs` gains **enum-member parity across the four platforms**: any prop typed as a named `Flare*` enum must declare the same member set everywhere. The previous signature pass compared prop *names* only, which is why a six-vs-five variant split stayed invisible while the contract claimed `platforms: "all"`. `FlareBrandTheme` is a registered exception (Vue additionally accepts a custom-theme object).

The list answers whether it had that message, so a host can tell "you are looking at it" from "it is not in this history".
  - Breaking: Flutter's `FlareMessageList.controller` changes type from `ScrollController?` to `FlareMessageListController?` (the controller owns the scroll controller and exposes it as `.scroll`), and Compose's `MessageList(listState =)` becomes `MessageList(state =)`. No aliases.
  - The handle is an entrance to each list's own locate path — same anchor, same reduced-motion rule, same stop-following-the-tail — not a second scroll implementation.
  - The located row lands in the middle of the viewport on all four kits. Compose left it against the top edge, so the messages that give it its context stayed off screen above it; the locate path now offsets by the viewport and the row's height, aiming with an estimate and correcting once the row is laid out, so the reader sees one movement rather than two. A row at least as tall as the viewport still starts at the top everywhere — there is nothing to centre, and pushing it down would hide the beginning.
- Round 5, native kits (Batch 5, 6 and 5.4):
  - The timeline opens at the newest message and follows the tail on Flutter, SwiftUI and Compose, keeps its position after the reader scrolls up, and offers jump-to-latest with a count — the same contract Vue has.
  - Message menus offer Copy only where there is text to copy: `flareCopyableText` (Flutter, SwiftUI) and the same rule inside Compose's `MessageActionSheet`; `messageMenuActions` and the sheets take the message `content`. The core still reports `canCopy` for image, voice and file messages (SDK gap S22), so each kit decides again.
  - Text links reach the host through `onOpenLink` on MessageList, MessageBubble and MessageContentView (Flutter's `onLinkTap` is renamed, with no alias). Where the host handles nothing, SwiftUI opens http/https with `openURL` and Compose with `LocalUriHandler`, both behind `safeExternalUrl`; Flutter does nothing, because the kit has no URL launcher and the lock files are frozen.
  - **Public icon fields take a semantic name, not a platform glyph** (breaking, no aliases): navigation items, settings rows, message menu entries, composer actions, buttons, icon buttons, empty states and workspace pane empty states on all three native kits. An unknown name draws the registry fallback and warns once per name in a debug build. `FlareDefaultIMNavigation` / `FlareDefaultContactNavigation` become `flareDefaultIMNavigation(strings)` / `flareDefaultContactNavigation(strings)` so their labels come from the strings table.
  - `FlareSettingKind` gains `action` on the three native kits, and a `value` row is no longer a control anywhere: no button, no focus stop, no callback, read as one "label, value" element. `myMuted` / `myPinned` become nullable, so a group setting that could not be read renders as 暂时无法读取 instead of a switch claiming "off".
  - **One pane below a usable chat width** on all four kits: `workspaceDualPaneMinWidth` (navigation + list + a 360 px chat; 752 with the tablet rail) compared against the width the layout measures for itself, divided by the text scale. Below it the workspace shows the host's active pane, keeps the navigation and routes a detail instead of overlaying it. `layoutChange` / `onLayoutChange` reports the presentation in use on AppLayout, IMAppKit and WorkspaceFrame (four platforms) and on DesktopAppShell (Vue and Flutter, the two whose shell arranges panes). Nine new cases in `spec/application-layout-vectors.json`.
  - Vue default navigation labels are translated at render time (`navigation.*`), so an entry that is still a kit default (same id and default label) reads in the interface language while a host's own wording is untouched. An English interface is unchanged.
  - Compose writes `@所有人`, the mention-all token the core parses (it wrote `@全体成员`, which never matched); Flutter and Compose render inline emoji-pack tokens in text bodies, Flutter with the pack's first frame.
